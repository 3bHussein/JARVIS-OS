# First-use guidance and reviewed quick capture

Home now shows a compact Make your daily workspace useful disclosure. It tracks only five actual recorded inputs/choices: profile, storage choice, sleep, food and a first note/commitment. It is not a health score, proof of integration completeness or a requirement to invent missing values. Recorded zero is different from unknown. Existing WHOOP/file freshness rules determine the Home values before the checklist sees them.

A session-only banner offers two explicit actions: Save current data encrypted, or Continue session-only. The save action persists the current server-session profile, notes and manual check-ins using the existing authenticated/revision-checked encrypted save route. It does not include unsaved form drafts, imported files, WHOOP tokens or chat. It passes the persistence choice with the save itself, rather than relying on an asynchronous checkbox state update. Failed writes leave existing data/drafts intact. Continuing session-only disables the pending remember choice and dismisses the banner for this unlock session only; it does not erase any older encrypted vault. Lock/reload resets this acknowledgement. No automatic saving consent is inferred.

Home also provides Quick capture for one note, task or workout. Enter text, an optional note time or mandatory task/workout time, plus duration. Review shows the exact text/type, configured IANA timezone, resolved date/time and duration. A recorded overlap is flagged. No entry is saved during preview. Confirm save is a separate action that creates one JARVIS entry through the existing owner save flow, not an external-app action or a model tool call. Change a field or go back to discard the preview and keep editing. A changed saved-data revision blocks the old preview and requires another review. Parent API conflicts/record limits still apply; failed drafts are retained.

No appointment time is inferred from natural language, a weekday label or health readings. Nonexistent/ambiguous DST times are rejected by the existing localInstant converter. A note without a time remains untimed and does not become a timed reminder. Successful portable restoration resets quick-entry drafts alongside planner/journal drafts. Lock unmounts private UI and clears these drafts. Personal notes enter model context only under the existing separate opt-in personal-context setting; this change adds no model/network scope.

Acceptance: FIRST01/02 cover missing/zero/recorded-choice semantics. UI38 covers preview-without-write, single confirmed save, stale-revision block and draft retention; UI39 covers one-click explicit encrypted save of current session edits and Arabic mobile bounds. All records/voice/providers are synthetic; actual owner data is not used in tests.
